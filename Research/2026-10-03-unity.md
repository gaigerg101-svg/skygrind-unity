# What Unity 6 URP offers that SKYGRIND isn't using yet

Research for the lead, 2026-10-03. This was read-only: nothing in either repo was edited and the Unity CLI was not run.
Project: Unity 6000.3.7f1, URP 17.3.0, branch `port/stage3` at `1128c2e`.

Each claim carries a tag:
- **[V]** I checked it in this repo (the file is named).
- **[W]** I read it in a fetched source (URL in the Sources list).
- **[S]** It comes from a search snippet only.
- **[U]** It's my inference.

None of the performance figures below was measured. Where a cost is given without a number, it is **[U]** and "not
measured".

---

## 0. Bottom line

1. **Most of the look we're missing is web FX that hasn't been ported yet, and URP already has the tools for it.** The
   numbers are already in `PortExport/config.json` **[V]**:
   - `post`: chromatic aberration pulses on hurt, dash, rank and speed, the colour grade, the low-HP vignette and
     desaturation, film grain, god rays, and per-quality toggles
   - `lightPool`, `motes`, `blobShadows`, `aura`, `ao`
   - `quality`: presets, the AUTO benchmark and dynamic resolution
   - `fx.enemyRimColor`, `fx.pop*`

   The Unity side has bloom, ACES, exposure and a vignette (`Game/Look.cs` **[V]**). Porting the rest is the cheapest
   big jump, and it stays inside rule 5.
2. **The map's shader ignores two URP features we already pay for.** `Shaders/Stone.shader` has no
   `_SCREEN_SPACE_OCCLUSION` keyword and no `_CLUSTER_LIGHT_LOOP` additional-light loop **[V]**. Meanwhile:
   - The SSAO renderer feature is active with After Opaque off and DepthNormals as its source (`PC_Renderer.asset`
     **[V]**). So the map probably gets no SSAO at all, while the depth-normals prepass and the AO pass still run
     **[U]**; this needs a frame capture to confirm.
   - Any point light we add (muzzle flash, the web's `lightPool`) would not light the map **[U]**, based on the shader
     source.

   Fixing `Stone.shader` comes before any lighting work.
3. **Agent constraints:** VFX Graph and Shader Graph assets are graph files you author in editor windows, which makes
   them a poor fit for an agent on a CLI **[U]**. The project's working pattern is hand-written HLSL plus objects built
   in code **[V]**, and it should stay that way. URP 17 lets a script inject render passes without editing the
   renderer asset, through `RenderPipelineManager.beginCameraRendering` and `EnqueuePass` **[W]**. Unity 6.4 removes
   Compatibility Mode, so new passes should be Render Graph only **[W]**. Render Graph is already on here
   (`m_EnableRenderCompatibilityMode: 0` **[V]**).
4. **Determinism:** everything below is view-side. The traps are:
   - Unity's own clocks (Shuriken, TrailRenderer, tween libraries) ignore our hitstop and pause unless they are fed the
     loop's `worldDt`.
   - Cosmetic randomness should keep coming from its own seeded `Mulberry32`, as `Game/Decals.cs` already does **[V]**.
5. **Retention and platform:**
   - Settings live in PlayerPrefs (`Game/GameSettings.cs` **[V]**), which is the Windows registry **[W]**, so Steam
     Auto-Cloud can't sync them. Auto-Cloud syncs files **[S]**.
   - There's no gamepad support (PORT-STATUS **[V]**). Steam Deck Verified needs full controller support, matching
     glyphs and text of at least 9 px at 800p **[W]**.
   - Unity announced official Steam / Steam Deck support at GDC 2026, with no version given **[W]**.

## 1. Audit: what the project uses now

- **Installed:** URP 17.3.0, Shader Graph (in `Library/PackageCache` as a URP dependency), Input System 1.18, uGUI 2.0
  (TMP), Burst 1.8.27, Collections 2.6.2, Mathematics, AI Navigation, Timeline, Test Framework, `com.unity.pipeline`
  0.8.0-exp, AI Assistant / Inference.
- **Absent:** VFX Graph, Cinemachine, Animation Rigging, Splines, any tween library, any Steamworks wrapper.

**URP asset** (`Settings/PC_RPAsset.asset`, the PC quality level, current quality 1 **[V]**):

| Setting | Value |
|---|---|
| HDR | on |
| MSAA | off |
| Render scale | 1, upscaling filter 0 (Automatic); no STP |
| SRP Batcher | on |
| GPU Resident Drawer | off |
| LOD cross-fade | on |

**Renderer** (`Settings/PC_Renderer.asset` **[V]**):
- Rendering path 2 (Forward+), native render pass on, depth priming off.
- One feature: SSAO (blue noise, source DepthNormals, After Opaque off, intensity 0.4, radius 0.3).
- No Decal, Full Screen Pass, Render Objects or custom features.

**The volume, built in code by `Look.Apply`** **[V]**:
- Bloom: threshold 1, intensity 0.8, scatter 0.6 (UnityTuning).
- Tonemapping ACES, ColorAdjustments `postExposure` 0.35.
- Vignette 0.22. This is a literal in `Look.cs`, not from `config.post.vignetteOffset/Darkness` or UnityTuning, so it
  falls under rule 5.
- The camera uses SMAA, HDR and post. The viewmodel is an overlay camera in the stack (`Viewmodel.cs` **[V]**).
- `Settings/DefaultVolumeProfile.asset` is URP's stock profile; its odd test components come from the package
  **[V]**.

**Shaders** **[V]**:
- Four hand-written URP shaders: `Stone`, `Sky`, `Field`, `Acid`. `Stone` borrows ShadowCaster, DepthOnly and
  DepthNormals from URP Lit through `UsePass`.
- Everything else uses `Universal Render Pipeline/Unlit` (the neon material: enemies, particles, decals, orbs) or `Lit`.
- Enemies set their colour through a MaterialPropertyBlock (`EnemyViews.cs`).

**FX** **[V]**:
- `Particles` (`EnemyViews.cs`) is `fx.poolSize` GameObject cubes, each with its own Renderer plus an MPB. That's one
  draw per live cube, and an MPB makes a renderer incompatible with the SRP Batcher **[W]**.
- `Decals.cs` is a pool of unlit quads (`fx.decalCount`).
- The only light is the directional key. `Look.cs` makes no point or spot lights.
- PhysX is off for gameplay: `SurvivalGame.cs:230` sets `Physics.simulationMode = SimulationMode.Script`, and the map
  has no colliders (`SurvivalBuilder.cs` header).

**Player** **[V]**:
- Standalone runs on Mono: only Android has a `scriptingBackend` entry.
- Incremental GC on, flip-model swapchain on, frame timing stats on, deterministic compilation on.
- Vsync off by default (`UnityTuning.VsyncDefault`). The FPS cap is set in `SurvivalGame.cs:516`.

**Web FX not ported** (`skygrind/src/fx/*.js` headers **[V]**, read only), each with its config section **[V]**:
- `post.js`: the chroma pulses, the tone-map choice (ACES / AgX / Neutral), film grain, god rays.
- `grade.js`: indigo shadows, warm highlights, ×1.1 saturation, desaturating as HP drops.
- `lightPool.js`: 3 pooled point lights that always exist, at intensity 0 when idle.
- `motes.js`: up to 900 camera-wrapped motes.
- `blobShadows.js`, `rimGlow.js`, `xray.js` (a ZTest-Greater silhouette pass), `dissolve.js` (the viewmodel's
  materialize effect).
- `aura.js` and `arcs.js` (style-rank arcs), `killConfirm.js`.
- `quality.js`: presets, AUTO and dynamic resolution.
- Fonts: Barlow Semi Condensed and Chakra Petch, shipped as woff2 under OFL (`skygrind/public/fonts`).

## 2. Area by area

The format for each entry is the Unity way, then cost, then pitfalls, then the call. Effort means an agent building it
from code: **S** under half a night, **M** about a night, **L** more than a night.

### (a) Particles, gibs, trails

**The options:**
- **Shuriken (`ParticleSystem`)** runs on the CPU and works everywhere.
  - Build it from code with `AddComponent<ParticleSystem>()` and fire bursts with `Emit(EmitParams, count)`.
  - One shared system per effect kind with `Emit` gave 0 GC per frame in one public test **[S]**.
  - URP's `Particles/Unlit` compiles procedural instancing (`#pragma instancing_options
    procedural:ParticleInstancingSetup`, in the package's `ParticlesUnlit.shader` **[V]**), so mesh-mode particles
    (cubes) instance.
- **VFX Graph** needs compute shaders **[W]**.
  - Steam Deck has compute through Vulkan or DXVK, so it would run there **[U]**.
  - Its assets are node graphs built in an editor window, which is agent-hostile **[U]**.
  - It pays off from about 10k particles up **[S]**. SKYGRIND's caps are 160 to 400 (`config.quality.particleCap`
    **[V]**).
  - **Don't.**
- **`Graphics.RenderMeshInstanced(RenderParams, mesh, submesh, matrices[])`** draws instances without GameObjects
  **[W]**.
  - Per-instance colour needs a shader with an instanced colour property **[W]**: a 30-line hand-written HLSL unlit
    shader.
  - This keeps `Particles`' own exact integrator and turns N cube draws into one **[U]**.
- **Collisions:** Shuriken's collision module uses PhysX colliders, and the map has none **[V]**. Use its "Planes" mode
  (the floor height at the burst), or keep integrating ourselves.
  - Reading the C# collider from view code is safe only if the query touches no shared scratch state. **Not
    checked**; `ThreeOctree` would need a look.
- **Trails:** use a pooled `TrailRenderer` per rocket or nail (`ProjectileViews.cs`).
  - `TrailRenderer` keys its points on `Time.time`, so during hitstop the trail keeps aging **[U]**.
  - Drive `emitting` and the width from the loop, or build a ribbon mesh ourselves, as the web's `arcs.js` does.
- **Hitstop and pause:** feed every view effect `worldDt`.
  - For Shuriken, set `main.simulationSpeed = 0` in hitstop, or call `Simulate(worldDt, true, false)` by hand **[U]**.
  - The views already render on `worldDt` (commit `26f7b1e` **[V]**).

**Recommendation: do.**
- Replace the GameObject cube pool with `RenderMeshInstanced` and an instanced unlit HLSL shader (**M**).
- Add a blocky death breakup: on `kill`, the dead enemy's view boxes (BlockyKit parts) detach and fly ballistically,
  with a floor bounce at the death height, then fade (**M**). It's render-only and draws no sim dice.
- **Risk:** low. Check the draw count before and after with `-skygrindBench 60`.

### (b) Decals: scorch, blood, bullet holes

**URP's Decal Renderer Feature** **[S]**:
- **DBuffer:** albedo, normal and MAOS, using a depth-normals prepass.
- **Screen Space:** decal meshes drawn over opaques after they render.
- **Automatic:** picks between the two.

**What it needs and allows:**
- A `DecalProjector` component with a material on the decal Shader Graph. `Shader Graphs/Decal` ships in the package
  (`Shaders/Decal.shadergraph` **[V]**).
- Decals sharing a material with GPU instancing on are instanced **[W]**.
- No decals on transparent surfaces **[W]**.

**Pitfalls:**
- DBuffer decals are applied inside the receiving shader. Our hand-written `Stone` never samples the DBuffer, so
  DBuffer decals would not show on the map **[U]**, based on the shader source.
- Screen Space draws after opaques, so it works with any opaque shader that writes depth. That needs Stone's DepthOnly
  pass, which it has **[V]**.
- Adding the feature means editing `PC_Renderer.asset` (`rendererFeatures` plus `m_RendererFeatureMap`) through an
  editor script while the Editor is live, which is a known fragile path **[U]**. Alternatively, write our own
  screen-space decal pass and inject it at runtime **[W, the EnqueuePass doc]**.

**Precedent:**
- ULTRAKILL patched its bloodstains to "account for curves, corners and edges" instead of floating flat **[S]**.
  Flat quads don't wrap corners; projectors do.
- Rust added blood splats behind shot characters, and Unity 5.6 instancing made its deferred decals "nearly free"
  **[S]**.

**Recommendation: later (M).**
- Keep the exact web quads for bullet holes (`effects.js` parity).
- Use URP Decals in Screen Space mode only for new splat kinds: COMET scorch, spitter acid stains, enemy splats.
- The look of enemy gore is GG's call (rule 7). Red-orange marks enemies only (rule 8).
- **Risk:** medium, because of the renderer-asset edit.

### (c) Post-processing on the URP Volume

The overrides available in 17.3 (`Runtime/Overrides/` **[V]**): Bloom, ChannelMixer, ChromaticAberration,
ColorAdjustments, ColorCurves, ColorLookup, DepthOfField, FilmGrain, LensDistortion, LiftGammaGain, MotionBlur,
PaniniProjection, ScreenSpaceLensFlare, ShadowsMidtonesHighlights, SplitToning, Tonemapping, Vignette, WhiteBalance.

**Do:**
- **Bloom.** 6.3 added Dual and Kawase filters next to Gaussian (`Bloom.cs` **[V]**; 6.3 notes **[W]**). Use
  Dual or Kawase on Low and on the Deck.
- **Tonemapping:** URP has only None, Neutral and ACES (`Tonemapping.cs` **[V]**). The web defaults to ACES and offers
  AgX (`post.js` **[V]**). Keep ACES. AgX would need a baked LUT through ColorLookup: **later**.
- **Grade** (`config.post.grade` **[V]**): use SplitToning or ShadowsMidtonesHighlights plus
  `ColorAdjustments.saturation`.
  - Below `post.lowHpAt`, blend in a second global Volume (higher priority, weight driven per frame by HP) carrying
    desaturation and the darker vignette (`lowHpDarkness`).
  - Switch the colour grading mode to HDR so grading happens before ACES **[U]**.
- **Vignette:** read `post.vignetteOffset` / `vignetteDarkness`. The 0.22 literal goes.
- **Chromatic aberration:** pulse it on `hurt`, `dash` and rank-up, and scale it with speed (`post.chroma*` **[V]**).
  - URP's intensity runs 0..1, a different unit from the web's offset (0.006). The mapping is a Unity-only number for
    UnityTuning **[U]**.
  - The web turns it off under reduced motion **[V]**.
- **Film grain:** `quality.presets.*.grain` **[V]**.

**Don't:**
- **Motion blur and depth of field** hurt readability at 30 m/s, and the web has neither **[U]**. The overlay viewmodel
  would also blur incorrectly.
- **TAA and STP:** STP needs compute, shader model 5 and TAA **[W]**. TAA brings ghosting wherever motion vectors are
  wrong **[S]**, and our enemies draw through MPBs and custom code. Stay on SMAA.

**Later:**
- **Lens distortion:** a small pulse on slam or dash. The web has none, so it's a design number.
- **Panini projection:** for the high end of CameraFeel's FOV ramp **[U]**.

**Outlines and rim:**
- Risk of Rain 2 moved to deferred to get cheap lights on projectiles, decals and "sobel outlines" **[W]**.
- Lethal Company is HDRP rendering at a fixed 860×520, plus one Shader Graph custom pass that posterizes and runs edge
  detection **[W, an Acerola analysis]**.
- For SKYGRIND, port the web's own rim glow (fresnel in the enemy shader) and x-ray. URP's Render Objects feature with
  Depth Test Greater is the documented way to draw a silhouette behind walls **[W]**. A second `ZTest Greater` pass in
  our own enemy shader avoids an asset edit **[U]**.
- A full-screen sobel outline through Full Screen Pass (any material, hand-written HLSL allowed) is **later** and is
  GG's call, because it changes the web's look.

**God rays** (`post.godRays`, High only **[V]**): a screen-space radial blur from the sun's screen position in one
injected Render Graph pass. That's cheaper than volumetrics **[U]**. **M**, later.

**Effort** for the "do" block: **S–M**. Every number already exists in config. **Risk:** low.

### (d) Lighting

**Forward+ is already on** **[V]**:
- It has no per-object light limit, and 256 visible lights per camera on desktop **[S]** (the 6000.1 light-limits page
  gives 256 for desktop **[W]**).
- URP 17.3 shaders gate the cluster light loop behind `_CLUSTER_LIGHT_LOOP`, as URP Lit does (`Lit.shader:151`
  **[V]**). Older tutorials say `_FORWARD_PLUS`, which no longer appears in 17.3's ShaderLibrary **[V]**.
- `Stone` needs that keyword plus `LIGHT_LOOP_BEGIN/END` to receive point lights.

**`lightPool`** (`config.lightPool`: max 3, blast and boss flashes, machine glow; `fx.popIntensity` / `popDistance` for
the muzzle and kill pops **[V]**):
- Port it as the web built it: lights that always exist, intensity 0 when idle.
- No shadows on point lights; a shadowed point light renders 6 shadow faces **[U]**.
- **S** once Stone is fixed.

**APV and baked GI:**
- APV needs baked GI, and every renderer that contributes has to be in the scene when the bake runs **[S]**.
- The map is built at load from PortExport (`SurvivalSetup.cs` header **[V]**), and the Grinder's pillars move
  **[V]**.
- **Don't.** Port the web's `ao` volume instead (`config.ao`: cell 1 m, range 0.34–0.72 **[V]**). That's a Texture3D
  built in code at load and sampled by Stone, giving a "GI" that fits a map built in code **[U]**. **M**.
- 6.3's SurfaceCacheGI exists in the package behind `#if SURFACE_CACHE` and hidden **[V]**. It's experimental:
  **don't**.

**SSAO:** either set After Opaque on (one field) or add `_SCREEN_SPACE_OCCLUSION` with `GetScreenSpaceAmbientOcclusion`
to Stone. The web's `quality.presets.*.ao` gives 0 / 0.55 / 0.6 **[V]**. **S**.

**Fog:**
- Linear fog is in (`Look.cs` **[V]**).
- URP has no volumetric fog. Unity's 2026 strategy thread lists it as missing from URP's roadmap **[W]**.
- The community standard is CristianQiu's Unity-URP-Volumetric-Light: MIT, Render Graph, Forward+, confirmed on Steam
  Deck, with transparents blending incorrectly **[W]**. It's a new package and a renderer-asset edit: **later**, as an
  opt-in High setting.

**Sky:** `Sky.shader` already draws the gradient and sun **[V]**. The web's skyline is missing (PORT-STATUS **[V]**):
**M**, view-only.

**Shadows:** 4 cascades at 2048 over 60 m with soft quality 3 is generous **[V]**. Use 2 cascades on Low or Deck **[U]**.

### (e) Shaders

**Shader Graph vs hand-written:**
- Shader Graph can now do Canvas (uGUI) materials **[W]**, URP custom lighting (6.3) and full-screen graphs **[W]**.
- But `.shadergraph` assets are JSON graphs normally edited in a window, and the project's working pattern is
  hand-written HLSL **[V]**.

**Do: one `SKYGRIND/Enemy` unlit HLSL shader** to replace URP/Unlit on the enemy views:
- The colour, kept compatible with the SRP Batcher where possible.
- `_Flash`, a hit-flash lerp to white, from the `hit` events.
- A fresnel rim in `fx.enemyRimColor`, HDR so bloom catches it (as `rimGlow.js` does).
- `_Dissolve`, a cell dissolve on death (`dissolve.js`'s 2.5 cm cells **[V]**).
- An optional vertex wobble for statuses.
- An x-ray pass (`ZTest Greater`, red-orange, about 0.35 alpha, fading out beyond 60 m, per `xray.js` **[V]**).

**Batching:** MPBs break SRP batching **[W]**. Per-renderer material instances of one shader still batch **[S]**. At
SKYGRIND's enemy counts either is fine **[U]**; check with the bench.

**Effort and risk:** **M**. Low risk, and it's the biggest readability gain after post.

### (f) Camera

**Cinemachine 3:** Impulse needs a CinemachineCamera plus an ImpulseListener **[W]**, so it takes over the camera
transform that CameraFeel drives. The custom shake is the web's `fx/trauma.js`, and `kicks` and `springs` are
golden-checked (PORT-STATUS **[V]**). **Don't.**

**Do instead (S):**
- The missing web feel items (PORT-STATUS **[V]**): the aim-lock FOV pinch, the dash edge tint (a vignette colour
  pulse on the post Volume), and trauma's viewmodel share.

### (g) Animation for the blocky enemies

**Animation Rigging** needs an Animator and a rig hierarchy. Our enemies are boxes built in code (`BlockyKit.cs`
**[V]**). **Don't.**

**Procedural, from C#** (it's all view-side):
- A spring flinch on `hit`, with the parts offset along the hit direction (springs.js is already golden-ported
  **[V]**).
- Squash on land, and lean into velocity.
- The death breakup from (a).

**Cosmetic physics** (if we ever want real tumbling):
- A second scene from `SceneManager.CreateScene(name, new CreateSceneParameters(LocalPhysicsMode.Physics3D))` gets its
  own PhysicsScene. Only its components simulate, and only when you call `Simulate` **[W]**.
- The debris would need colliders for the map in that scene: a MeshCollider from the stone mesh **[U]**.
- Global Script mode stays as it is.
- 6.3 and 6.4 let you strip the physics module **[W]**. Don't, if this path stays open.
- **Later (M).** Ballistic parts with a floor plane get about 80% of the look **[U]**.

### (h) UI motion, UI shaders, fonts

**Tweening** (the UI is built in code):
- **PrimeTween:** zero allocations, `Tween.UIAnchoredPositionY`, `Alpha`, `ShakeCamera`, Sequences, installed from
  the npm registry **[W]**. Its licence is custom: free and commercial use allowed, no redistributing the source **[W]**.
- **LitMotion:** MIT, zero allocations, needs Burst and Collections (both already installed **[V]**), installed from a
  git URL, with TMP character animation **[W]**. A `ManualMotionDispatcher` gives a custom clock **[S]**.
- **DOTween:** allocates per tween; Pro costs money **[S]**.

**Recommendation:** ask GG before adding any package. Without one, `UiFeel.cs` (130 lines **[V]**) already does
hand-rolled easing; extend it with a small easing set and a `worldDt` / unscaled clock (**S**). If a library goes in,
use LitMotion: MIT, its dependencies are already present, and it has a manual clock.

**UI shaders:** a hand-written variant of UI/Default for glow, scanlines and wipes, for the screens' transitions
(**S**). The Canvas Shader Graph is an option, but its graphs are editor-authored **[W/U]**.

**Fonts:**
- Unity imports TTF and OTF, not woff2 **[S]**.
- Take the OFL TTFs of Barlow Semi Condensed and Chakra Petch from Google Fonts. That's simpler than converting the
  woff2 files.
- An editor script calls `TMP_FontAsset.CreateFontAsset(font, size, padding, GlyphRenderMode.SDFAA, 1024, 1024,
  AtlasPopulationMode.Dynamic)` **[S]**, adds the characters, saves it with `AssetDatabase.CreateAsset`, and adds the
  atlas texture and material as sub-assets with `AddObjectToAsset` (the usual pitfall when this isn't done **[U]**).
  Set the asset to Static for builds.
- The 16 px minimum at 1080p becomes 11.9 px at 800p, which clears Deck's 9 px floor **[W]** and is near its 12 px
  recommendation.
- **S.** Note that CLAUDE.md rule 8 says TMP's default font stays until the theme fonts are converted, so this is that
  conversion.

### (i) Platform and retention

**Steam wrappers:**
- **Steamworks.NET:** MIT, a thin wrapper with 100% coverage of the C++ API, so Valve's docs apply directly **[W]**.
- **Facepunch.Steamworks:** MIT, idiomatic C#, works with IL2CPP, version 2.5.2 from April 2026 **[S]**.
- Unity said at GDC on 2026-03-11 that official Steam support is coming, including Steamworks integration and
  Deck-tuned Linux players, with no version named **[W]**. **Check the 6.4 to 6.6 notes before picking a wrapper**
  (not checked).

**Do now (S–M):**
- Move settings and records from PlayerPrefs to JSON files under `Application.persistentDataPath` (one `.sav`
  extension). PlayerPrefs on Windows is the registry **[W]**, and Steam Auto-Cloud needs only a path pattern and a
  quota, with no code **[S]**.
- The sim's events (`kill`, round records, `RunMoments`) can feed achievements and stats from the view side.
  Leaderboards suit the score line.
- Unity Gaming Services: not relevant to a single-player Steam game **[U]**.

**Steam Deck:**
- **Verified needs:** full controller support with no settings changes, matching glyphs, 30 fps at 800p, text at
  least 9 px at 1280×800, and 1280×800 or 720 supported **[W]**.
- **Prerequisite:** port `input/gamepad.js` (`config.gamepad` exists **[V]**) to the Input System.
- **Builds:** Valve tests a native Linux build if one exists, otherwise Proton **[S]**.

### (j) Performance

- **SRP Batcher** is on **[V]**. MPB renderers drop out of it **[W]**: particles, enemies, power-ups, traps (MPBs in
  10+ view files **[V]**). The instancing in (a) fixes the largest group.
- **GPU Resident Drawer** **[W]**:
  - Needs Forward+ (we have it), compute, BRG variants set to Keep All, and MeshRenderers only.
  - The 6000.6 docs add: no MaterialPropertyBlocks **[S]**.
  - It pays off with many objects sharing a mesh.
  - Our scene is mostly unique code-built meshes plus MPBs, so the gain is low **[U]**. **Later.**
- **Occlusion culling:** Umbra needs static geometry baked in the editor, and the map is built at load **[V]**.
  **Don't.**
- **IL2CPP vs Mono:**
  - Unity recommends IL2CPP to ship. Builds are slower; runtime is often faster **[S]**.
  - **Risk to rule 3:** C++ compilers may contract float operations (FMA) differently from Mono's JIT **[U]**.
  - Trial it once with `-skygrindGolden` and the replays on an IL2CPP Player. Switch only on 0 mismatches.
  - **S** to try, **M** if anything diverges.
- **Burst and Jobs:** fine for view-only work (motes, particles). Keep them out of `Skygrind.Core` (rule 3) **[U]**.
- **Latency:**
  - `QualitySettings.maxQueuedFrames` defaults to 2 on PC; 1 trades framerate for lower latency **[W]**.
  - Flip-model swapchain is already on **[V]**.
  - Read input as late as possible before the step loop **[S]**.
  - Expose `maxQueuedFrames` as a setting **[U]**.
  - NVIDIA Reflex for Unity: not checked.
- **Dynamic resolution** (`config.quality.dynamic` **[V]**): either `ScalableBufferManager.ResizeBuffers`, or
  `renderScale` on an `Instantiate`d copy of the URP asset assigned to `QualitySettings.renderPipeline`. The copy
  reverts after Play mode, so the project asset isn't rewritten **[S]**. The Editor-rewrite trap is the same one
  `Look.cs` notes for shadow distance **[V]**.
  - On Deck: render scale about 0.75 with FSR1 (URP's upscaling filter) **[U]**.
  - Unity 6.6 brings a unified upscaler framework with DLSS4 and FSR3 **[W]**.
- **Deck GPU:** 8 RDNA 2 CUs, up to 1.6 TFLOPS FP32 **[S]**. Our unlit neon look is cheap. The costs to watch are
  SSAO, the shadow cascades and any volumetrics **[U]**.

### (k) How shipped Unity games did these things

- **ULTRAKILL:**
  - Unity 2019.4.40 **[S, Hakita on X]**.
  - Its PSX vertex wobble and affine texture warping are player sliders **[S]**.
  - "The retro visual style is that visuals are very easy to read at a glance" **[W, 80.lv]**.
  - Bloodstains were patched to wrap corners, and there's a "bloodstain chance" option **[S]**.
  - A public recreation spawns its decals from particle collisions **[S]**; that's not Hakita's code.
  - Lesson: readability first, then style effects as player options.
- **Risk of Rain 2:** went deferred so it could attach lights to projectiles, monsters and items, and got cheap decals
  and sobel outlines **[W]**. Our equivalent is Forward+ with a light pool **[U]**.
- **Lethal Company:** HDRP features almost entirely stock, a fixed low render resolution, and one custom Shader Graph
  pass for posterizing and edges **[W, via Acerola]**. Lesson: one signature full-screen pass on top of stock features.
- **Valheim:** low-res textures and low-poly models under modern lighting, fog and post **[S]**. It moved to Unity 6 in
  2026 and added a cheap Low SSAO option **[S]**.
- **Rust:** blood splat decals behind hit characters, and decal instancing made them nearly free **[S]**.
- **Cult of the Lamb:** custom lighting work for its 2.5D setup, with a lighting specialist **[W]**.
- **Hollow Knight:** Unity's Particle System, 2D Toolkit and PlayMaker **[S]**, so nothing directly reusable here.
- **Escape from Tarkov:** not checked.

## 4. Ranked top-12 Unity upgrades

How to verify, for every item:
- Capture with `capture_game_view` from one SliceSmoke step, with `CaptureDir` set, same spot and same seed, before
  and after.
- Move the image to `Logs/shots/`.
- Bench with `-skygrindBench 60` on AC, with the power plan checked.
- Run 437 tests, 22 replays and 90 golden. No Core changes are expected.

### Night A: "light and lens" (6 items, all S, no new packages, no edits to the renderer asset)

1. **Stone receives SSAO and point lights.** Impact **H** (it unlocks items 2 and 3), effort **S**.
   - Add `_SCREEN_SPACE_OCCLUSION` and `_CLUSTER_LIGHT_LOOP` with the light loop to `Stone.shader`. Drop the opaque
     texture if nothing samples it.
   - **Verify:** capture a pillar base with SSAO on and off, and a temporary point light next to a wall.
2. **post.js on the Volume.** Impact **H**, effort **S–M**.
   - The chroma pulses (hurt, dash, rank, speed), the split-tone grade, the low-HP Volume (desaturation plus vignette),
     and grain by preset. Numbers come from `config.post` / `quality`; the unit mappings go in UnityTuning; the 0.22
     literal goes.
   - **Verify:** captures at full HP, at 30% HP, and in the frame after a dash.
3. **lightPool plus muzzle and kill pops.** Impact **H**, effort **S**. Needs item 1.
   - **Verify:** capture a COMET blast in the Grinder's shadow, and a muzzle flash against a near wall.
4. **Blob shadows** (`config.blobShadows`). Impact **M**, effort **S**.
   - One instanced quad mesh.
   - **Verify:** capture husks on the ground at Low, where there's no shadow map.
5. **Motes** (`config.motes`). Impact **M**, effort **S**.
   - One mesh, with a wrap-around vertex shader in HLSL.
   - **Verify:** capture the sky-facing view at dusk, and check the bench delta.
6. **Theme fonts.** Impact **M**, effort **S**.
   - Barlow Semi Condensed and Chakra Petch, built by an editor script.
   - **Verify:** captures of TITLE, the HUD and RESULTS. Check the smallest text is at least 16 px at 1080p.

### Night B: "enemies and impacts" (4 or 5 items)

7. **`SKYGRIND/Enemy` shader**: rim, hit flash, death dissolve, x-ray pass. Impact **H**, effort **M**.
   - **Verify:** a husk at 30 m against the horizon; the hit-flash frame; a dissolve mid-death; a husk behind a wall
     with the x-ray on.
8. **Instanced particles plus the blocky death breakup.** Impact **H** (feel), effort **M**.
   - **Verify:** the draw count in the bench log, and a capture of a THUNDERCLAP kill.
9. **AO volume** (`config.ao`). Impact **M**, effort **M**.
   - **Verify:** captures of corners and slab bottoms, compared against the web's capture of the same spot.
10. **God rays** (`post.godRays`, High only, one injected Render Graph pass). Impact **M**, effort **M**.
    - **Verify:** a capture looking toward the sun past the skybridges.
    - Optional in the same night: the IL2CPP trial with `-skygrindGolden`. Impact **M**, effort **S**.

### Night C: "ship-shape" (platform and retention)

11. **Quality presets, AUTO, dynamic resolution, a Deck profile.** Impact **M** (and **H** for the Deck), effort **M**.
    - Dual-filter bloom on Low, 2 cascades, FSR1 at a 0.75 render scale on the Deck.
    - **Verify:** the bench across presets, and a 1280×800 capture for text size.
12. **Saves to JSON, the gamepad with glyphs, a Steam layer behind a flag.** Impact **H** (retention, Deck), effort
    **M–L**.
    - Needs GG's go for the Steamworks wrapper and the app id. Check Unity's official Steam support first.
    - **Verify:** play a run on the pad only, with every menu reachable; on a fresh profile, settings survive a
      reinstall through a file copy.

**Prerequisites and decisions for GG:**
- Item 2's chroma unit mapping and item 7's flash and dissolve timings are new Unity-only numbers, so they go in
  `UnityTuning` or `Design/unity-config.json` (rule 5).
- Gore and splat looks fall under enemy design (rule 7).
- Any new package needs an OK: LitMotion, a Steam wrapper, the volumetric fog package.
